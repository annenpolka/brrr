# https://github.com/pytest-dev/pytest/issues/14971

revision: 8ca24f9936a7765e3ccf551efb6398e4517a31d858343564eb58f0ea8c9aca90

Passing test files on the command line in the order `nested/a.py parent/top.py nested/b.py` makes fixtures defined in `nested/conftest.py` invisible to the last file on pytest 9.1.1. The same command passes on pytest 8.4.2, and passes on 9.1.1 when the two nested files are adjacent or when the directory is given instead of the files.

Minimal reproduction (Python 3.10.19, macOS, no plugins beyond the defaults):

```
tests/conftest.py
    import pytest
    @pytest.fixture
    def root_fixture():
        return "root"

tests/services/conftest.py
    import pytest
    @pytest.fixture
    def nested_fixture():
        return "nested"

tests/services/test_a.py
    def test_a(nested_fixture):
        assert nested_fixture == "nested"

tests/services/test_b.py
    def test_b(nested_fixture):
        assert nested_fixture == "nested"

tests/test_top.py
    def test_top(root_fixture):
        assert root_fixture == "root"
```

```
$ python -m pytest tests/services/test_a.py tests/test_top.py tests/services/test_b.py -q -p no:cacheprovider
pytest 9.1.1 -> 2 passed, 1 error      (ERROR at setup of test_b: fixture 'nested_fixture' not found)
pytest 8.4.2 -> 3 passed
```

What we traced (please treat as a pointer, not a diagnosis): with a bare file argument directly under an ancestor directory, `Session.collect` sets `handle_dupes=False`, so `_collect_one_node` bypasses its cache and re-collects `tests/services`, producing a second `Directory` node instance for the same path. Since 9.x matches fixture visibility by node identity in `FixtureManager._matchfactories` rather than by nodeid prefix, fixtures registered on the first `tests/services` instance are invisible to items collected under the second one. Two real projects hit this from developers running a hand-picked file list; `pytest tests/` is unaffected.
