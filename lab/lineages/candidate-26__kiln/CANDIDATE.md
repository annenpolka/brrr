# candidate-26 — kiln

## Primitive

A generated artifact is a claim about a source world; kiln reconstructs the firing **lot** from headers, generator recipes, and imports, then reports whether the claim still holds and whether siblings fired together have since split.

The object is a **lot** (artifacts that claim the same recipe). The verb is the missing question next to `make` / `ninja -d explain` when there is no graph: *were these oracles minted together, and is that mint still true?*

## Why this might not exist

`ninja -d explain` answers "which declared input is newer." Bazel sandboxes declared inputs. Snapshot testers compare bytes to a golden. `git status` is silent when `oracles_generated.test.ts` last moved on 2026-07-20 and `specs/notifier.pkl` last moved on 2026-07-28 — same clean tree, tests green, four language projections of one spec no longer a single firing.

The recurring annoyance: a spec-driven repo (`just spec-gen`, `@generated by tools/spec-gen.ts from specs/*.pkl`) has no Makefile. Developers regenerate some projections, commit the ones whose bytes changed, and leave inert oracles behind. Headers name one `.pkl` and go **blind** to `import "patterns.pkl"`. Checkout clusters mtimes so "is this stale?" from `ls -l` lies.

## Four primitives considered

1. **illicit-rebuild** — strace a command, compare opened files to a declared recipe. **Discarded as conventional** (`ninja -d explain`, Bazel sandbox, `make -d`).
2. **hostbound** — grep tests for `/Users/`, `C:\Users\`, hostname, TZ offsets. **Discarded as conventional** (flaky-test greps, docker path lint). Folded a thin BOUND tag into kiln rather than making it the tool.
3. **afterheat** — borrowed freshness: an artifact looks new because checkout rewrote mtime, not because it was regenerated. Unusual, but it is a *verdict* (CLOCK) not a new object. Kept inside kiln.
4. **kiln** — generation lots recovered from artifact claims. **Implemented.**

Not leftover-name hunting, not ghosts, not inverse-printf, not path-conditions, not wait-for graphs, not call protocols, not copy detectors.

Python 3.10+, stdlib only. `./kiln` is the CLI. Exit 0 on scan; `--check` exits 1 on DATED/SPLIT/ORPHAN; usage errors exit 2.

### Before the improvement (v0.1)

Fixture selftest already held: DATED / SPLIT / BLIND / CLOCK / DIRTY / ORPHAN / FORGED on a three-commit ugly repo whose header omitted `hidden.pkl`.

Real repos, first pass:

**relico** — the money shot, already visible:

  FRESH  docs/SPEC.md                             fired 2026-07-28

Unit and e2e oracles are eight days behind the spec. Renderer and SPEC.md refired. Git is clean.

Noise that drowned it:

- **CLOCK flood.** After checkout, every DATED file also got CLOCK because "mtime not older" was treated as "mtime says fresh."
- **False generator.** `oracles_generated.proptest-regressions` bound to `tools/spec-gen.ts` because the tool guessed `spec-gen` for any `*generated*` name.
- **tenaoshi** missed `contracts/testcases/*.json` (no header, no `generated` in the filename) even though `spec-gen.ts` lists them as outputs.
- **voidtrace** treated `tools/spec-gen/src/render.ts` as an artifact (the template string `Generated from specs/main.pkl` sits in the first 16 lines) and split JSON files into extra lots.
- **koyomi-trace** bound every `corpus_*generated.mbt` to `generate_eventspec_corpus.py`.

### After the improvement (v0.2)

1. Rebuild reasons are **content**: blob at fire commit vs working tree, so `why` names files whose bytes actually moved (`specs/notifier.pkl`, undeclared `specs/patterns.pkl`).
2. CLOCK only when mtimes disagree by >120s **and** the artifact is clean. Checkout clusters and in-progress dirty regens drop out.
3. Generator output lists (comments + `path: "…"`) pull headerless members into the lot.
4. Lot key is the declared source, not the `by` token — missing `by` still joins the firing.
5. Tight generator bind: corpus → `generate_corpus.py`, metamorphic → `generate_eventspec_corpus.py`. No repo-wide spec-gen guess.

## Surprises

- A *content-identical* regen does not move git last-commit. Relico unit oracles were rewritten on 2026-07-28 (mtime lockstep with SPEC.md) but git still says 2026-07-20 because the bytes did not change. kiln's DATED is correct: the *world* moved; this projection is inert.
- Headers name one pkl. The live world is `import "patterns.pkl"` (relico/tenaoshi) or fifty files under `specs/` (voidtrace). BLIND is the default, not an edge case.
- `ninja -d explain` would not have helped: there is no ninja graph.

## Failures

- CLOCK can still fire on voidtrace `AI_UX.md` / `CONTRACTS.md` when a recent checkout or touch makes those files newer than a dirty spec by more than two minutes. That is closer to truth than v0.1's flood, still not a proof of "would make rebuild."
- Untracked recipe outputs (new tenaoshi JSON cases) have no fire commit, so reasons fall back to `dirty-source` instead of content blobs.
- BOUND=tz on koyomi is real (oracles encode `+09:00`) and also *intentional*. The tag is a hint, not a defect.
- Does not re-run the generator. INERT (regen would be a no-op) vs DATED (regen would change bytes) is not distinguished without invoking `just spec-gen`.

## Suggested mutations

- Store/compare `sourceFingerprint` (voidtrace already stamps `sha256:` in JSON) against a hash of the import closure, without running pkl.
- `--repair`: emit a `just spec-gen` / per-projection command for DATED members only.
- Cross-projection clause-id skew as a *lot* column (relico unit tests ICN-\* only; rust tests 80 clauses). v0 skipped this because the layers are *supposed* to differ; a mutation could treat SPEC.md as the oracle of record and report untested clause IDs.
- Watch mode: re-scan after `just spec-gen` and show the lot collapsing from SPLIT to FRESH.

## Kill / keep

**Keep.** The object (a firing lot recovered from claims) is not make, not ninja, not snapshot test, and it found a real eight-day split in a clean git tree on the first dogfood pass.
